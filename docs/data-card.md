# Data card

## Dataset and source

- Dataset: synthetic TPC-H `lineitem` table generated by DuckDB's `tpch` extension (`dbgen`).
- Use: custom small-file, Parquet layout, query-latency, and energy-estimation experiment. This is not an official TPC-H benchmark result.
- The generator writes a `manifest.json` with DuckDB version, scale factor, row count, ordered schema, compression, file SHA-256, intended use, and privacy note. Preserve the manifest with local results.
- The generator's license and redistribution terms must be reviewed before distributing generated benchmark data; the project can be reproduced from the generator instead of submitting data.

## Schema and minimization

Only the standard synthetic TPC-H `lineitem` schema is approved: `l_orderkey`, `l_partkey`, `l_suppkey`, `l_linenumber`, `l_quantity`, `l_extendedprice`, `l_discount`, `l_tax`, `l_returnflag`, `l_linestatus`, `l_shipdate`, `l_commitdate`, `l_receiptdate`, `l_shipinstruct`, `l_shipmode`, and `l_comment`. The generator does not ingest personal records. Keep the dataset limited to this table and the columns needed for the experiment.

## Governance control and measured evidence

Run `scripts/governance_check.py` with the generated Parquet and generator manifest. It checks the exact column allowlist, required provenance fields, observed row count, and—when an ingestion manifest is present—the source file hash, micro-batch row/schema metadata, and output file checksums. It writes a JSON audit with passed and failed file counts even if a check fails. Unit fixtures cover both compliant and deliberately non-compliant schemas.

The control is narrow: column names and provenance do not reveal whether a field's values are identifying or sensitive, and they do not establish a privacy guarantee or quantify re-identification risk. Generated data provenance and tool versions should be retained when results are shared.
